REPForge - uruchomienie na telefonie krok po kroku
===================================================

Ten plik opisuje najprostszy sposob uruchomienia aplikacji na telefonie.
Masz trzy opcje:

1. Web mobile - otwierasz aplikacje w przegladarce telefonu.
2. Android app - instalujesz debug APK przez kabel USB.
3. Android app + real API - aplikacja na telefonie laczy sie z backendem z komputera.


WAZNE: localhost na telefonie oznacza telefon, nie komputer
------------------------------------------------------------

Dlatego na telefonie zawsze uzywaj adresu IP komputera w sieci lokalnej,
np.:

http://192.168.1.25:3000

Zamiast:

http://localhost:3000


KROK 1 - znajdz IP komputera
----------------------------

W PowerShell uruchom:

ipconfig

Znajdz aktywna karte Wi-Fi/Ethernet i skopiuj IPv4 Address.
Przyklad:

192.168.1.25

W dalszych krokach zamien YOUR_LAN_IP na ten adres.


KROK 2 - web mobile w mock mode
-------------------------------

To jest najprostszy tryb. Nie potrzebujesz backendu ani Dockera.

Na komputerze:

.\scripts\run-frontend-local.ps1 -Mode mock -Mobile

Na telefonie otworz w przegladarce:

http://YOUR_LAN_IP:3000

Przyklad:

http://192.168.1.25:3000


KROK 3 - web mobile z prawdziwym API
------------------------------------

Uruchom backend i baze danych:

docker compose --profile real up -d postgres backend

Uruchom frontend tak, zeby telefon widzial API:

.\scripts\run-frontend-local.ps1 -Mode real -Mobile -ApiUrl http://YOUR_LAN_IP:5064/api

Na telefonie otworz:

http://YOUR_LAN_IP:3000


KROK 4 - przygotuj Android SDK
------------------------------

Do instalacji APK na telefonie potrzebujesz Android Studio i Android SDK.

Zainstaluj:

- Android Studio
- Android SDK Platform 36
- Android SDK Build Tools
- Android SDK Platform Tools

Potem sprawdz konfiguracje:

.\scripts\android-doctor.ps1

Jesli wszystko jest OK, zobaczysz:

[android-doctor] Android setup looks ready.


KROK 5 - wlacz debugowanie USB na telefonie
-------------------------------------------

Na telefonie Android:

1. Wejdz w Settings.
2. Wejdz w About phone.
3. Kliknij kilka razy Build number, az wlaczysz Developer options.
4. Wroc do Settings.
5. Wejdz w Developer options.
6. Wlacz USB debugging.
7. Podlacz telefon kablem USB do komputera.
8. Na telefonie zaakceptuj komunikat o zaufaniu dla komputera.

Sprawdz czy komputer widzi telefon:

adb devices

Jesli adb nie jest w PATH, uzyj pelnej sciezki z Android SDK, np.:

C:\Users\YOUR_USER\AppData\Local\Android\Sdk\platform-tools\adb.exe devices


KROK 6 - zbuduj APK dla telefonu
--------------------------------

Najpierw uruchom frontend dla telefonu.

Mock mode:

.\scripts\run-frontend-local.ps1 -Mode mock -Mobile

Albo real API:

docker compose --profile real up -d postgres backend
.\scripts\run-frontend-local.ps1 -Mode real -Mobile -ApiUrl http://YOUR_LAN_IP:5064/api

W drugim terminalu zbuduj APK:

.\scripts\build-android-debug.ps1 -ServerUrl http://YOUR_LAN_IP:3000

APK pojawi sie tutaj:

frontend-app\android\app\build\outputs\apk\debug\app-debug.apk


KROK 7 - zainstaluj APK na telefonie
------------------------------------

Najprosciej:

.\scripts\install-android-debug.ps1 -ServerUrl http://YOUR_LAN_IP:3000

Jesli masz podlaczone wiecej niz jedno urzadzenie:

.\scripts\install-android-debug.ps1 -ServerUrl http://YOUR_LAN_IP:3000 -DeviceId DEVICE_ID

DEVICE_ID sprawdzisz przez:

adb devices


KROK 8 - test po instalacji
---------------------------

Po uruchomieniu aplikacji na telefonie sprawdz:

1. Czy aplikacja sie otwiera.
2. Czy login/register dziala.
3. Czy przejscia Dashboard / Workouts / Progress / Profile dzialaja.
4. Czy da sie utworzyc trening.
5. Czy da sie wystartowac trening.
6. Czy timer dziala po wyjsciu z treningu.
7. Czy floating timer pokazuje sie poza ekranem treningu.
8. Czy finish workout nie pokazuje surowego HTTP 500.
9. Czy upload video analysis pokazuje kontrolowany beta state.


Najczestsze problemy
--------------------

Problem: telefon nie otwiera http://YOUR_LAN_IP:3000

Rozwiazania:

- Upewnij sie, ze telefon i komputer sa w tej samej sieci Wi-Fi.
- Uruchom frontend z flaga -Mobile.
- Sprawdz IP komputera przez ipconfig.
- Odblokuj port 3000 w Windows Firewall.


Problem: aplikacja otwiera sie, ale API nie dziala

Rozwiazania:

- W real API mode uzyj http://YOUR_LAN_IP:5064/api, nie localhost.
- Uruchom backend:

  docker compose --profile real up -d postgres backend

- Sprawdz readiness API:

  http://YOUR_LAN_IP:5064/health/ready

- Odblokuj port 5064 w Windows Firewall.


Problem: android-doctor pokazuje Android SDK: MISSING

Rozwiazania:

- Zainstaluj Android Studio.
- Otworz SDK Manager.
- Zainstaluj Android SDK Platform 36.
- Zainstaluj Android SDK Build Tools.
- Zainstaluj Android SDK Platform Tools.
- Uruchom ponownie terminal i odpal:

  .\scripts\android-doctor.ps1


Problem: adb devices nie pokazuje telefonu

Rozwiazania:

- Wlacz USB debugging.
- Zmien kabel USB.
- Odblokuj ekran telefonu.
- Zaakceptuj popup "Allow USB debugging".
- Uruchom:

  adb kill-server
  adb start-server
  adb devices


Problem: po zmianie IP aplikacja dalej laczy sie ze starym adresem

Rozwiazanie:

Zbuduj APK jeszcze raz z nowym ServerUrl:

.\scripts\build-android-debug.ps1 -ServerUrl http://YOUR_NEW_LAN_IP:3000
.\scripts\install-android-debug.ps1 -ServerUrl http://YOUR_NEW_LAN_IP:3000


Najkrotsza sciezka do pokazania aplikacji na telefonie
------------------------------------------------------

1. Znajdz IP komputera:

   ipconfig

2. Uruchom web mobile mock:

   .\scripts\run-frontend-local.ps1 -Mode mock -Mobile

3. Na telefonie wejdz:

   http://YOUR_LAN_IP:3000

To wystarcza, zeby szybko pokazac aplikacje jako web mobile.

Jesli chcesz pokazac natywna ikonke/aplikacje Android, zrob jeszcze:

4. Zainstaluj Android Studio + SDK.
5. Sprawdz:

   .\scripts\android-doctor.ps1

6. Zbuduj i zainstaluj:

   .\scripts\install-android-debug.ps1 -ServerUrl http://YOUR_LAN_IP:3000
